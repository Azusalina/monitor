A transparent modular KDE Plasma 6 desktop widget. Usage is in [../docs/README.md](../docs/README.md); architecture and verification notes are in [../docs/description.md](../docs/description.md).

### Version 1.17 — smoother flows, global focus shortcuts and native splitting

System sampling and independent ping deadlines are 200ms. Dashboard polls at 200ms. Sparkline now animates history samples as well as audio spectra, interpolating from the currently displayed values so updates remain continuous if a transition is interrupted. Missing measurements stay unknown. Ping concurrency/timeout limits are unchanged; slow hosts cannot deliver 5 Hz. Faster collection increases CPU/network work, especially for GPU process-engine counters.

`native/` builds the local Monitor.Native QML plugin using Qt6, KF6GlobalAccel and libplasma. DesktopBridge registers two QAction global shortcuts with unique applet IDs and refuses conflicts/invalid unmodified keys. Only main widgets register shortcuts. ConfigTimers stages portable key strings; Preview stages the settings but does not register global actions. Defaults are Meta+Ctrl+Alt+C and Meta+Ctrl+Alt+S.

DesktopBridge creates real same-containment Plasma applets with createApplet geometry hints. The parent scans live children to hide detached modules; deletion or merging restores them. Shared profile synchronization preserves notes/task content, config and colors; local native topology is not exported to profiles. The initial sync waits for native initialization so clone metadata is applied before profile loading. If the original parent is removed, remaining children become standalone views; a newly created owner has the existing documented session-restart limits. Returning is supported to the original parent in the same containment, not as a cross-screen containment transfer. Note/to-dos remain one module; Timers contains both clocks.

Configure → Flows adds flowRefreshMs (100–5000ms, default 200) and audioRefreshMs (50–1000ms, default 100). Native KConfig and preview Apply/Cancel wiring stage the settings; the existing schema-derived profile store validates and saves them. The page scrolls on small windows.

Dashboard polls with its configured interval and a transient per-view client identifier. CPU/RAM/GPU sampling follows the fastest unexpired client demand; ping cadence is chosen per target from the clients requesting it. Demands expire after max(2s, 3 intervals), and at most 64 clients are retained. A short interruptible scheduler wait allows a newly opened fast view to wake a slow collector promptly; slow probes yield rather than spin. Slow/blocked pings still cannot overlap. Refresh intervals govern reads/samples, not the compositor's animation frame rate. Multiple independent views can keep shared hardware sampling faster than a slower view's selected interval.

### Version 1.21 — durable project Timecount

Timecount is a separate splittable module; the existing countdown and session stopwatch retain their behavior. Its default view shows a cumulative stopwatch for a selected project and Start/Pause. While recording, choosing another project starts that project and pauses the previous one atomically. The > detail page shows all-time/Today/Week/Month totals, active days, current/best daily streak and a 53-week Monday-first activity grid. Hover a square for the local date and recorded duration; intensity thresholds are >0, 15m, 1h and 3h. Future days are dimmed; the grid scrolls horizontally in narrow widgets. Total hours are unbounded by a 24-hour display. Configure → Timecount adds and renames up to 32 project IDs, preserving historical time across renames, and sets a #rrggbb accent for the clock and heatmap. Configuration drafts are applied through the existing Apply/OK persistence flow.

The Python timecount.py module owns a locked SQLite WAL database in XDG_STATE_HOME/monitor-dashboard/timecount.sqlite3, falling back to ~/.local/state. Project IDs are stable within each settings profile; a profile allows one running project. Only sync/start/pause/release are accepted by the native-client-only /timecount endpoint. There is no API to reset, subtract, overwrite durations or delete history. Daily milliseconds only increase; renamed/removed metadata never erases rows. SQLite transactions serialize starts from different views, so intervals are not counted twice. Each two-second view heartbeat renews a six-second lease; normal last-view closure releases it immediately. Abrupt client failure can account up to the lease boundary, then pauses. Shutdown checkpoints pending elapsed time, and restart always loads counters paused. The two-second checkpoint interval bounds potential loss after a hard process/power failure. Time uses the monotonic clock, excluding suspended time on Linux; wall time is used only for local daily attribution. Intervals split across local midnight and DST boundaries; changing wall time cannot subtract stored totals. SQLite uses synchronous=FULL and the database is created with mode 0600. Idle state sync avoids rewriting unchanged project names.

Main/detached views inherit a shared TimecountOwner where possible; separate instances use distinct client IDs but read the same profile's counters. Profile changes release the old lease. Polls retain normal button enabled/opacity state, and a user command during a poll is queued once, keeping the 1.20.1 anti-flicker behavior. Configuration/profile JSON stores project IDs/names and accent, not history. Back up the live database with sqlite3.Connection.backup(), or stop the service before copying database/WAL files. No user history is written by the isolated regression fixture.

### Version 1.22 — fitted CAVA blocks, independent color and clear headroom

Block density changes only the stripe pattern, leaving the measured waveform and analyzer resolution unchanged. Configure → Media adds cavaBarCount (8–128, default 32), cavaBarColor (empty or #rrggbb; defaults to the curve color), and cavaHeadroom (5–60 percent, default 20). ### Version 1.23 — current-session Timecount and hidden vertical indicators

Switching to another project also finalizes the former session and starts the next from zero. All-time totals, daily/weekly/monthly summaries and the activity grid remain on > details and continue accumulating without reset. The main view's left-side Last annotation shows that project's last completed local-time interval and duration; narrow widgets put the same small annotation below the clock on the left.

An additive sessions table records start, last-checkpoint, end and credited milliseconds, indexed by profile/project/latest ID. Every active checkpoint updates its session and daily totals in the same transaction. Stop, switch, last-view closure, configuration removal, lease expiry and graceful backend shutdown close the interval once. On process recovery, unfinished rows close at their last durable checkpoint, excluding offline time. Existing daily rows are not rewritten, and legacy aggregate data is not assigned invented session timestamps. API state adds session_seconds, session_started_at and last_session while retaining the existing total and day/statistics fields. The existing pause action remains wire-compatible but now means Stop/end session in the UI.
